# ADR-0058: Shared notes: a git repo of markdown, edited through SilverBullet at `notes.bnei.dev`

**Status:** Accepted, not live. This PR adds the app and its authentik
blueprints; SilverBullet's own setup (users, OIDC, git remote) is a one-time
manual step (Rollout).
**Date:** 2026-10-17
**Related:** [ADR-0039](0039-authentik-identity-layer.md) (Native OIDC tier,
local admin kept as break-glass), [ADR-0050](0050-public-oidc-client-for-native-apps.md)
(`core_default_app_access=false`, Decision 9 on `sub_mode`),
[ADR-0054](0054-netbird-control-plane-hosting-only.md) (NetBird's dashboard,
the precedent for a UI-held setting), `MohammadBnei/notes`,
`MohammadBnei/shared-plugins`.

## Context

M BN and N MG share business work in Notion. Notion is opaque to git and
awkward as Claude context, and both run Claude Code. They want one place
that holds their pages, readable and writable by both Claudes as plain
files, and still editable in a browser with a Notion-like feel.

That rules out every wiki that keeps pages in its own database. Options
weighed on 2026-10-17:

- **Confluence**: Data Center took no new subscriptions after 2026-03-30.
- **Docmost**: closest to Confluence, but Postgres-canonical; git sync has
  "no plans" (docmost#1171).
- **Wiki.js**: database-canonical, git is a mirror; v3 still beta.
- **AppFlowy**: the open server was archived 2026-09-11; the maintained one is
  closed source, free tier one seat.
- **LeafWiki** (Go): split-pane editor, pulls only on demand, writes an id
  into every file's frontmatter.
- **Sveltia CMS**: GitHub-API commits, rich text — but CMS-shaped, and logs in
  with GitHub tokens, not authentik.
- **SilverBullet 2.12** (Rust server, MIT): markdown files on disk are the
  only store, git sync built in, three-way merge of concurrent edits,
  native OIDC.

## Decision

1. **SilverBullet, platform-common tier**, `ghcr.io/silverbulletmd/silverbullet:2.12.1-slim`
   at `notes.bnei.dev`, one Longhorn PVC at `/data`, `Recreate`.
2. **Markdown in git is canonical.** The space `notes` is a clone of
   `MohammadBnei/notes` at `/data/notes`. SilverBullet runs in Managed
   revisions mode: it commits each person's edits as that person, merges and
   pushes to `main` with a per-space deploy key, and pulls every minute. It
   never force-pushes or rebases. `main` carries no branch protection — the
   deploy key could not bypass it.
3. **The space is the repo root, and Claude material lives under `.claude/`.**
   SilverBullet treats a space nested inside a larger repo as unmanaged (no
   commits, no sync), so `pages/` in a bigger repo was not an option. Dot-dirs
   are invisible to it and refused by its file API, so `.claude/` cannot be
   edited from a browser.
4. **Shared Claude plugins live in a second repo**, `MohammadBnei/shared-plugins`,
   a Claude Code marketplace edited only through git. SilverBullet commits
   about every 30 s while someone types; in the notes repo that would make
   every keystroke burst a plugin "update", and let a browser session edit
   hook scripts that then run on both laptops. The notes repo registers the
   marketplace in `.claude/settings.json`.
5. **Login is authentik, native OIDC**, not forwardAuth, so commits carry the
   real author. `sub_mode` is left at `hashed_user_id` (ADR-0050 Decision 9):
   SilverBullet binds an account to issuer + subject.
6. **A custom email scope mapping that says `email_verified: True`**, on this
   provider only. authentik's managed mapping always says `False`, and
   SilverBullet refuses a login without a verified email. Honest here: only
   the accounts named in the policy blueprint can pass, and SilverBullet only
   admits users an admin pre-created by that email.
7. **A `shared-notes` group, declared in its own policy blueprint**, members
   akadmin and nicozlat. Not `platform-admins`, which is ArgoCD and Grafana
   admin.
8. **Egress is fenced.** Any writer can make the server fetch a URL
   (`/.proxy`). The namespace's NetworkPolicy allows DNS, Traefik's VIP on
   443 and the internet, and denies the rest of RFC1918, the cluster ranges
   and link-local — the first egress policy in this cluster.
9. **The Board is GitHub Projects + Issues** on the notes repo, not markdown.

## Accepted deviation: settings held by the app, not by git

SilverBullet's users, OIDC configuration and git remote are set in its
Dashboard and stored on the PVC (`users.json`, `authentication.json`, the
space's revisions settings). There is no env var or file to declare them —
the NetBird dashboard precedent (ADR-0054). Two secrets therefore live
outside Infisical:

- the **OIDC client secret**, copied from Infisical into
  `authentication.json`;
- the **deploy private key**, generated by SilverBullet.

Both are also in the Longhorn backups on Garage. Rotation: rotate the client
secret in Infisical, restart the authentik worker, re-paste it in Admin →
Authentication. Regenerate the deploy key in the space's Revisions settings
and replace it on GitHub.

## Consequences

- History gets merge commits (`git merge --no-edit`), and a conflict halts
  sync until someone resolves it in SilverBullet, while Claude's pushes keep
  landing on GitHub. The docs call git sync "primarily a backup mechanism"
  and the merge "experimental". Fallbacks if two-way use misbehaves:
  SilverBullet as the only writer of pages, or Sveltia CMS.
- The editor feels like Obsidian (live-preview markdown, slash commands), not
  Notion blocks. Upgrade path: SilverBullet's Lua and plugs, then a fork.
- A stalled sync is invisible from GitHub. A log alert waits for a confirmed
  sync-error log line.
- N MG's browser access depends on ukubi. Git and Claude Code do not.

## Rollout

1. Merge. ArgoCD creates the namespace, PVC and pod; authentik applies both
   blueprints (the policy one may need one more worker restart if it ran
   before the application existed).
2. The notes repo deliberately has no `index.md`: the wizard seeds one into
   the empty space folder, and connecting the remote in step 5 then asks once
   to combine unrelated histories — with no file on both sides, the combine
   cannot conflict. Keep it that way until the space is connected.
3. Wizard: the local admin (break-glass), space `notes` bound to
   `notes.bnei.dev`, folder `/data/notes`.
4. Admin → Server: primary URL `https://notes.bnei.dev`. Admin →
   Authentication: generic OIDC, issuer
   `https://authentik.bnei.dev/application/o/silverbullet/`, client id and
   secret from Infisical (`SILVERBULLET_OIDC_CLIENT_*`). Users: pre-create
   M BN and N MG by their authentik email, write on `notes`.
5. Space → Revisions: Managed, connect `git@github.com:MohammadBnei/notes.git`,
   "Deploy key for this space", add it on GitHub with write access, check
   remote every minute.
